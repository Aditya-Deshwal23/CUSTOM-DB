# CUSTOM-DB v1.0.0 release notes

Release notes for the v1.0.0 tag. The tag and hosted release are created by the
release workflow after the corresponding commit is pushed.

## What's included

- C++17 page storage, buffer pool, B+ tree, bounded SQL execution, and
  checksummed redo WAL recovery.
- Crow API and same-origin vanilla dashboard, centralized validated
  configuration, JSON logs, and graceful shutdown.
- Non-root multi-architecture container packaging with SBOM/provenance on
  tagged image builds.
- Reproducible CI, sanitizer, API/dashboard, SQL differential, and crash
  testing.
- The local `linux/arm64` Docker image size fell from 146 MB before packaging
  to 56.9 MB for the final multi-stage image; see
  [the measurement and reproduction command](../BENCHMARKS.md#container-image-size).

## Benchmark headline

The local five-repetition comparison is documented in
[BENCHMARKS.md](../BENCHMARKS.md): 10,000 rows, 1,000 warm point reads per
engine per run, Apple M5 arm64 / macOS 27.0.1 / Python 3.14.7 / SQLite 3.53.4.
Median results:

| Implementation / path | Median throughput | Median p50 | Median p95 |
|---|---:|---:|---:|
| CUSTOM-DB, HTTP + JSON | 6,124 reads/s | 158.5 us | 193.0 us |
| SQLite, Python `sqlite3` | 666,426 reads/s | 1.38 us | 1.79 us |

This is intentionally labeled as an end-to-end path comparison, not a fair
engine-core comparison. Reproduce with
[`tools/benchmark_sqlite.py`](../../tools/benchmark_sqlite.py).

## Crash-recovery evidence

- CI crash workflow: 200 seeded iterations per push or pull request, covering
  parent-process SIGKILL, crash after commit append, and interruption during
  recovery. The test runner reports exact completed iterations and failures.
- Nightly crash workflow: 5,000 seeded iterations.
- Container proof: actual terminal capture at
  [`../assets/recovery.cast`](../assets/recovery.cast); it shows the API write
  loop, `SIGKILL`, recovery log, `--check`, recovered rows, and clean
  SIGTERM/checkpoint.

| Evidence run | Configured crash iterations | Kill/recovery cases |
|---|---:|---|
| Push / pull request CI | 200 | Parent `SIGKILL`, commit append, interrupted recovery |
| Nightly CI | 5,000 | Same seeded crash harness |
| Recorded container demonstration | One real container kill/restart | 1,752 acknowledged writes, 1,753 recovered rows, integrity check, graceful stop |

These are configured CI run counts and the checked-in local capture. A hosted
release should link the exact passing workflow run rather than infer a release
result from the configured iteration budget.
